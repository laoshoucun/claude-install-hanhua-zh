# Opus 5.5 三个新玩法：搭乐高，改宜家说明书，复刻塞尔达

> 原文链接：[https://www.laoshoucun.com/claudedt/3360](https://www.laoshoucun.com/claudedt/3360)

Opus 5.5 发布已经好几天，热度一点没降。

原因也不复杂。网友还在往里塞新玩法。

这两天最出圈的一个，来自抱抱脸的产品负责人 Victor Mustar。

他给这个模型出的题目是：用真正买得到的乐高零件，搭一只实物大小的 Microduck。

它是抱抱脸与 Pollen Robotics 联手做的小型双足机器人。开卖之后销售很猛，4 秒就能出一只。Victor 想做的，是它的乐高版本。

结果整个活儿，被这个模型一个人包了。

先看设计。模型用上了 1113 个真实存在的乐高零件。它逐一检查 3204 处连接，还验算了零件碰撞与重心。

更夸张的在后头。它顺手生成了一本 141 页的搭建说明书，一共 237 个步骤。外加一份能直接拿去下单的零件清单。连展示视频也是它自己做的。

说明书被作者传到了抱抱脸社区上。大家都好奇一件事：照单买齐，到底能不能拼出来。

作者说他已经带着孩子在家试了，结果还得再等等。

别急着说这只是网友的炫技。Claude 那边的负责人 Boris Cherny 也跑进了评论区，他的第一反应是想把这东西接上一台 3D 打印机。

看到这里，事情的味道就不一样了。

以前测一个模型会不会写代码，无非让它做个网页，或者画一张矢量图。现在网友直接让它设计一件现实里真能搭起来的物件，顺手把工程验证、文档和采购清单一起做了。

乐高只是开头。

宜家的组装说明书，大家都不陌生。没有几句话，全靠一张张小人和零件的示意图。

有人喜欢这种极简设计。更多人的体验是看不懂，还烦。

于是有人想了个方向：把纸面说明书直接变成一部 3D 配音教学视频。

原本静态的二维步骤，被重做成了 3D 场景。零件在哪，怎么移动，下一步装到哪，全用动画演示，还配了解说。

视频作者本人是位技术投资人。他的评价挺直接，这个模型靠写代码，一夜之间变成了一个真能用的视频模型。

严格说，它并没有突然学会直接吐视频。

有意思的地方正在这里。它先看懂说明书。然后自己写代码，搭场景，控制物体运动。最后把结果渲染成视频。

代码正在变成一层万能中间层。模型在疯狂写代码，用户这一侧却不用看代码。

AI编程的门槛就这样往下掉，判断力的门槛反而在往上抬。

更硬核的玩法出现在游戏上。

一位网友拉来了 Opus 5.5、GPT-6 Astra 和 Fable 5.1。任务只有一个：复刻《塞尔达传说：时之笛》。

一行人照着游戏最开始的演示片段，从零重做场景。他们强调没有套用现成的完整游戏引擎，大量游戏逻辑和视觉内容都让模型自己搭。

眼下的成果，离一部完整的《塞尔达》当然还很远。

但问题在于这一点。直到前不久，我们还在用「让 AI 画一只骑自行车的鹈鹕」来测模型懂不懂世界。

现在一群人拿一款刚发布几天的模型，去做乐高，去做 3D 教程，去做视频，甚至去做游戏。

这也不是因为大家突然变得特别有创意。

Opus 5.5 发布之后，在 Code Arena: WebDev 榜单上拿了第一。价格比排第二的 GPT-6 Astra (Max) 低了 60%。

榜单说明它的编程和智能体能力又强了一截。

网友这几天的折腾，给出了一个更具体的答案。当写代码这件事足够强之后，「会写代码」最后会变成什么。

走到这一步，vibe coding 这个名字甚至有点窄了。

不过也有眼尖的网友发现了问题。

那本 141 页的说明书里，还有悬空零件，也有根本没锁死的连接。

也就是说，模型已经能把一个想法包装得很像完成品。

从「看起来能做」到「真的能做」，中间还差最后一段路。

对做 AI工具 的人来说，这套玩法是一次提前的提醒。工具越强，越难回答的问题就越具体：你想让它做什么。

宁可用它先跑一版原型，也别指望它一次给出能交付的成品。
