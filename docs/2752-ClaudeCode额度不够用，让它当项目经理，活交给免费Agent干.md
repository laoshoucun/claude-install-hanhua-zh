# Claude Code 额度不够用，让它当项目经理，活交给免费 Agent 干

> 原文链接：[https://www.sz003.com/codexdt/2752](https://www.sz003.com/codexdt/2752)

七天里两个一百美元的号被封，他退回二十美元那一档。钱不是重点，重点是额度。二十美元的 Claude Code，一个稍大的任务跑两下，一周的量就没了。他没认输，换了个思路，给 AI 找了个领导。

老板是他自己，只出想法和目标。项目经理交给 Claude Code，负责理解意图，拆任务，排方案。执行交给 WorkBuddy，按方案一步步做。贵的额度只花在想清楚这件事上，落地的活走另一边每天登录能领的免费积分。这层很薄。

两边怎么对话，中间得有个传话的。WorkBuddy 的端口，会话编号，消息格式，这些东西它不用碰，全丢给一个叫 gateway 的中间层。它只调几个工具，这层把任务递过去，成果再带回来。

这么分的好处，是把贵的算力和便宜的算力放在该放的位置。拆任务，判断路径，写清楚每一步要什么，这些事最吃模型能力，也最容易一步错步步错。真正动手改文件，跑命令，点按钮，反而不需要那么贵的脑子。

还有个容易被忽略的点。他说 AI 比人更会写提示词，因为 AI 更懂 AI。让它去指挥另一个 Agent，信息传递比自己上手快，也少掉很多来回确认。

至于封号，他的说法很实在。目前没有万全的解法，他能给的只有经验，电脑环境干净，网络环境干净，二十美元的号没那么容易被封。这话听着像废话，但用过的人知道，这两条恰恰最容易忽略。

这套架构也有边界。三层结构多一个中间层，就多一次误解的机会。任务描述在中间层转一手，语义会不会走样，取决于那层做得够不够薄。另外免费积分是别人的规则，今天有明天不一定有。真要靠它跑业务，得留一条退路。

如果你也被额度卡住，可以先试最小的一步。把手上那个想不清楚就先别动手的任务挑出来，只让 Claude Code 做拆解，方案写成人能看懂的样子，再交给便宜的 Agent 执行。跑通一次，你就知道自己该在哪一层省钱。
