# Anthropic 把工作台改名游乐场：不写代码也能跑通 Claude 接口

> 原文链接：[https://www.laoshoucun.com/claudedt/3396](https://www.laoshoucun.com/claudedt/3396)

换了名字，也换了活法

9 月 28 日，这家公司把用了快两年的开发者工具改了名。原来的工作台，现在叫游乐场。

官方给出的说法很短。想试试 Claude 的新能力，不必再写代码。

表面看只是换了个名字。

但真正的变化在别处。原本偏工程化的接口，正在被做成普通人也能上手的可视化产品。

门槛被拆了。

不写代码，也能把接口跑起来

过去想探底这套接口的能力，普通人往往要经历一遍工程受难史。

配置虚拟环境，导入开发包，配置密钥，手写参数结构，捕获报错。还没开始验证业务想法，半天时间已经耗在排错上。

这套流程对做AI编程的人来说不算什么。对绝大多数不写代码的人来说，它就是一道墙。

新版游乐场把底层能力拆成了图形化模块。

模型切换和参数调节都在右侧。滑块一拖，输入框一填，秒级响应。

高阶功能也做成了模板。工具调用和结构化输出，还有代码执行与联网搜索，勾选就能测。不用手写协议映射。

侧边栏可以随时展开，看到原始的请求与响应报文。词元消耗和上下文调用逻辑一目了然。

真正的杀手锏在最后一环。你在网页里调通的一切，可以一键导出成代码。

先点出来，再把代码拿走。

过去发生在开发环境里的高试错成本，被整体平移进了浏览器。

把给程序员用的接口，做成人人可用的产品。这就是这次改名的全部用意。

顺序变了。

工作台这个名字，死得不冤

它为什么要放弃旧名字。

因为「工作台」这三个字自带劝退属性。一听就是给工程师准备的。你得先学会怎么用工具，才能开始干活。

对刚接触大模型接口的人来说，光这个名字就能劝退一半。

换成「游乐场」就不一样。潜台词很直白，进来玩就是了。

这不是一家公司在做的事。另一家头部公司有同名的游乐场，还有一家叫 AI Studio。三家巨头，三套模型体系，最后在产品命名上撞到了一起。

名字趋同的背后，是行业在形成同一套范式。

聊天窗口负责让普通人体验 AI。游乐场负责把体验者变成开发者。

位置调过来了。

与其把接口当成只有工程师才碰的东西，不如先让人玩起来。宁可多花两分钟在界面上点选，也别把半天耗在配环境上。

这笔账很好算。

下一个战场在控制台

拿游乐场做一个代码审查机器人，结果挺有意思。

这边 1.9 秒返回正确的结构化结果，用掉 102 个词元，成本 0.0029 美元。导出的脚本直接能跑。

另一边 6.2 秒出答案，消耗大约 2900 个词元。

导出的文件里塞满了完整对话记录。还得手动删掉前面的内容，加上打印语句，才能运行。

差别在导出的形态。

这边导出的是自包含脚本。可以存进代码仓库，在流水线里直接调用。那边导出的是一份交互记录，你得自己拆。

两边的思路完全不同。用一句话概括，提示词属于代码，不属于网页控制台。

这个对照说明了一件事。同样的任务，两家给的东西去向不同。一边给的是能直接带走的成品。一边给的是过程的记录。

过去两年，所有人都在抢聊天入口。几家头部产品打得头破血流。

但接下来要抢的，是谁能让最多的人把模型真正接进自己的产品里。

这家公司今年的动作很密集。智能体开发包让开发者用两门主流语言就能构建智能体。消息接口加了按需压缩，长对话自动瘦身，不用手动管理上下文。

动作密集的背后是一个判断。模型能力本身很难再拉开身位。谁能把接入成本压得更低，谁就更容易被选中。开发者不会为了一点性能差距，去重写一遍集成代码。

模型能力越来越复杂，接口参数越来越多。但表层入口必须越来越简单。

这就是游乐场存在的意义。底层再复杂，用户看到的只是一个框，几个滑块，一个运行按钮。

往前看一步。模型调用和工具调用，结构化输出和智能体编排，都能通过可视化界面完成。

到那一天，「接口用户」和「普通用户」之间的那堵墙，会薄到几乎不存在。

墙在变薄。

对普通人来说，变化也很直接。以前要找人代劳的事，现在自己在网页上就能试一遍。

以前你得先学会编程，才能做出一个AI工具。

现在只需要先点出来，再把代码拿走。
